Step 1

Understand the system

Work here happens in stable work blocks: stretches that survive interruption and can be picked up cold. The agent's half of that promise is mechanical - a resume pointer written to disk before anything risky, an append-only journal as the source of truth, task checkpoints that name their evidence, and one ritual that seals each block. Your half is a single page called the console, which watches without interrupting.

Privacy, data sharing and telemetry - the honest version

Three truths, stated plainly:

  1. This system phones home to no one. There is no telemetry, no analytics, no update check, no CDN. The hooks and tools make exactly zero network calls. The one exception is obsctl analyze, which is off by default and only ever talks to the endpoint you configure - and with a local Ollama endpoint, even that never leaves your machine. API keys live in your environment or a gitignored .env, never in a committed file, and the tests prove a key placed in config is ignored.
  2. Claude Code itself talks to Anthropic. Your conversation, and files the agent reads, go to the Claude API - that is how Claude Code works, with or without this system, under your account's data settings. This system neither adds to that traffic nor reduces it. What it adds is a local copy: the record captures events so you can inspect and analyze what happened on your own disk.
  3. The record is radioactive, and treated that way. Raw captured events contain prompts, file contents and tool output verbatim (measured at ~70% of capture volume). So the raw record lives in a sibling folder outside the repo, where git structurally cannot reach it; only allowlisted metadata (event names, timestamps, token counts, an integrity anchor) is ever committed. A git push can therefore never publish a prompt, a file body, or a secret from the record - and a CHECK-phase gate fails the ritual if any committed file so much as names your home directory.
Verify, don't trust. Every claim above is a grep away: 
# the only network call site in the whole system (analyze, opt-in):
grep -rn "urllib.request" .claude/tools/ .claude/hooks/
# what the hooks are wired to do:
cat .claude/settings.json
# the redaction allowlist that gates what can ever be committed:
python3 -c "import json; print(json.load(open('.claude/config/observe.json'))['seal_allowlist'])"
# the test suite, including the secrets-never-reach-segments proofs:
python3 .claude/tools/tests/run_tests.py
Claude Code will also ask you once whether to trust this project's hooks before running any of them - nothing here executes until you say yes.
Step 2

Set it up

Requirements: bash, python3, git, and a browser. Nothing to install - no pip, no node.

Pick your path

SituationDo this
New / empty repoDownload dot-claude-iff-fresh.zip from the Releases page, unzip into the repo root, follow its START-HERE.md.
Existing repoDownload dot-claude-iff-adopt-kit.zip, unzip it anywhere outside your repo, open Claude Code in your repo, paste the one instruction from the kit's ADOPT.md. Your files are merged, never overwritten - a pre-existing .claude/ is the designed case.
Just exploringClone this repo; it runs on itself. Everything below works here directly.

Three switches, once

  1. Trust the hooks. On your first Claude Code session in the project it asks whether to run this project's hooks. Say yes - then prove it worked: 
    echo '{}' | bash .claude/hooks/heartbeat.sh
cat .claude/state/heartbeat.json   # a timestamp means the harness is alive
  2. Open the console. 
    python3 .claude/console/console.py
# then open  http://127.0.0.1:7717/console.html
    Give it half the screen, Claude Code the other half - terminal, VS Code and the desktop app all work the same. (The SessionStart hook auto-starts the server afterwards.)
  3. Tell it how you're billed (optional). If you use a Claude subscription, you are done: costs read "in plan". On API billing, set billing: "api" in .claude/config/model-prices.json and fill in your verified prices.
Step 3

Start and learn

Six small exercises, each ten minutes or less. Every card tells you the context, what you'll use, the exact action, what fires underneath, and where to look on the console. Do them in order: each one teaches the next one's vocabulary.

01Watch a heartbeat
Context

Before trusting the instruments, see one instrument respond to one event. The heartbeat is the simplest: an O(1) timestamp written at the end of every agent turn.

You'll use
Claude Code heartbeat.sh obs-capture.sh
Do

Ask Claude Code anything at all - "list the files in this repo" is enough - and let the turn finish.

Underneath

The turn's end fires the Stop event. heartbeat.sh overwrites state/heartbeat.json, and obs-capture.sh appends the raw event to the out-of-repo record's spool. Telemetry fails open: if either hook broke, your turn would still complete.

Console
NOW the pulse dot turns live and the age resets to seconds.
02Open a session and set a pointer
Context

The heartbeat cannot survive a mid-turn crash; the pointer can, because it is written to disk before risky work begins. It is the single habit that makes any session resumable cold.

You'll use
statectl.py state/journal.jsonl
Do
python3 .claude/tools/statectl.py start --session first-steps
python3 .claude/tools/statectl.py pointer "learning the system, exercise 2 of 6"
Underneath

Each command appends one line to journal.jsonl - the append-only source of truth - then rebuilds the projections (session.json, HANDOFF.md). Projections are derived and disposable; the journal is the record. Next session, the SessionStart hook will print your pointer into the fresh context automatically.

Console
NOW the resume pointer and the journal feed show your entries within seconds.
03Plan a real task
Context

A task file is a work block's skeleton: a goal with a definition of done, plan steps that each name their evidence, and a checkpoint a stranger could resume from.

You'll use
/plan-task tasks/
Do

In Claude Code, type /plan-task and describe something small and real from your project. Read the file it creates under .claude/tasks/ and notice every plan item's "done when".

Underneath

The skill instantiates tasks/_template.md, registers the task in STATUS.md, and sets the journal pointer. On resume, checkpoints are treated as claims to verify against disk, never facts - "reality wins" is the rule that makes stale checkpoints harmless.

Console
WORK your task appears with its status and next action.
04Answer the agent through the queue
Context

When the agent needs you, it must bring the full situation: the CLI refuses to open a queue item without a plain-language context and one concrete action. Your side of the contract is the copy button.

You'll use
statectl.py need the copy-context button
Do

Create a practice item, then answer it from the console:

python3 .claude/tools/statectl.py need open --title "Practice question" \
  --category decide --context "This is exercise 4: a stand-in decision so you can try the \
copy-context loop end to end. Nothing is blocked." --action "Copy this from the console and answer it"

On the console, press the item's copy context button, paste into Claude Code, type your answer after My answer:, and send. Then let the agent resolve it (or do it yourself: statectl.py need resolve <id> --answer "...").

Underneath

Open, amend and resolve are append-only events in needs-human.jsonl; the board you see is a projection, sorted severity-first (SEV0 halts everything, SEV3 is discretionary). The paste text is built server-side, so panel and clipboard can never disagree.

Console
NOW needs-human panel: severity chips, "what's going on", "what to do", the copy button.
05Read the system map
Context

Every component - agent, tool, hook, store, human - has a card with curated relations. The map is those cards compiled: orange is agent, blue is code, green is data, gold is human.

You'll use
the MAP tab anatomist mapctl.py
Do

Open MAP and click journal. Everything unconnected fades; its neighborhood raises to the front. Click it again for the detail popup; press Esc to clear. Find the two components sitting in the unplaced band and read why honest unplacement beats confident wrong placement.

Underneath

mapctl.py scan auto-discovers components and drafts cards; the anatomist agent curates relations with cited evidence; a two-tier lint fails the ritual on a wrong edge but only warns on a missing one. A wrong edge is worse than a missing one.

Console
MAP focus mode, backbone/flows views, click-through to sources.
06Close the block: run the ritual
Context

One command ends a session properly: check (does reality match the record?), polish (curate memory, rebuild every derived surface), publish (seal the record, commit, ask before pushing), evolve (propose at most three evidence-backed improvements, you approve).

You'll use
/project-memory checkctl.py retro-analyst anatomist
Do

In Claude Code, type /project-memory. Read what CHECK reports before anything is written. When the retro proposes changes (or says NO-CHANGES - a good outcome), decide. Expect your first retro to be NO-CHANGES.

Underneath

The phases share one transaction id: PUBLISH refuses unless CHECK and POLISH completed in the same ritual, so a half-built state can never be committed as whole. Every generator in the system runs here and only here - the anti-rot law. Sealing copies raw events into segments through a field allowlist; verbatim content stays out of anything committed.

Console
STORY a new point on the dual clock (wall time / tokens), plus refreshed map and work panels.
